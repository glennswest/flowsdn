# v0.8.0 — foundation scheduling and catalogue coverage

Catalogues all 539 configuration keys, including class and alias metadata.
488 defaults resolve directly; 51 unresolved defaults require explicit values
and provenance. Complete registry construction fails until those gaps are
resolved. Help metadata and area-specific validators remain incomplete.

Adds a caller-owned reconciler run loop with bounded rounds, change and prune
wakeups, shutdown handling and completion-based retry deadlines. Initialization
continues to gate pruning; callers with stricter startup needs retain their
explicit fence. Refresh and batch target operations remain forthcoming.

Adds synchronous script commands for existence, permissions, renaming, symlinks
and recursive removal. Operations stay within the workspace; recursive removal
has depth and entry limits. Absolute symlink targets are explicitly unsupported.
Subprocesses, background work and networking adapters remain forthcoming.

Adds build identity metadata with deterministic commit timestamps, explicit
development-build marking, JSON presentation and build-info metric labels.
BPF metadata remains explicitly unavailable until BPF builds exist. This crate
provides data for future binaries; it does not add a networking executable.

Resolves the health crate naming conflict: `flowsdn-health` owns the module
registry; `flowsdn-healthcheck` is reserved for active network health checking.

This is a source-only foundation prerelease. Networking compatibility remains
unvalidated.

Validation: 180 tests pass in both debug and release. Formatting, Clippy,
x86-64 and arm64 Linux musl compile checks, and dependency policy checks pass.
Arm64 runtime execution and whole-binary reproducibility remain unvalidated.
