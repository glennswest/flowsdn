# flowsdn.io custom resources

flowsdn defines 22 custom resources in `flowsdn.io/v1alpha1` (#325). Their schemas are
Cilium v1.20.1's storage-version schemas (vendored byte for byte at
`crates/flowsdn-k8s/crds/`, commit `7d68cfb394`, Apache-2.0), projected to flowsdn's
own identity (ADR-0017): `Flowsdn*` kinds, `flowsdn*` plurals, the category `flowsdn`
(`kubectl get flowsdn` lists them all) and one `fs*` short name each. Cilium's own short
names are not registered, so flowsdn installs beside Cilium without a collision.

What ships:

- **CRD manifests**: [`deploy/stormcos/manifests-kubernetes/crds/`](../deploy/stormcos/manifests-kubernetes/crds/),
  one file per kind, generated by `flowsdn_k8s::crd` (`FLOWSDN_WRITE_CRDS=1 cargo test -p
  flowsdn-k8s --test crds`). A test fails if a shipped file differs from its generation.
  Every schema keeps the reference's validation: enums, patterns, formats, bounds, list
  types and the CEL `x-kubernetes-validations` rules. Each CRD has one served/storage version
  `v1alpha1`, the reference's `status` subresource and printer columns, and the label
  `io.flowsdn.k8s.crd.schema.version: 1.33.11`.
- **Examples**: [`crates/flowsdn-k8s/testdata/crs/<plural>/`](../crates/flowsdn-k8s/testdata/crs/).
  Each kind has `minimal.yaml` (the smallest object the API server admits),
  `realistic.yaml` (a representative production object) and `reject-*.yaml` cases the
  API server must refuse, each headed `# expect: <reason>`.
- **Validation**: `flowsdn_k8s::schema::validate` checks an object against a CRD offline,
  the way the API server does on create. It applies defaults first, then checks types,
  required and unknown fields, enums, patterns, formats, bounds, list-map keys and
  `oneOf`/`anyOf`/`allOf`/`not`. It evaluates CEL in the subset the schemas use
  (`has`, field selection, comparisons, `isIP`, `! && ||`); transition rules (`oldSelf`)
  are skipped, as on create. Every example and reject case runs through it in the tests.
- **RBAC**: the agent's `flowsdn-crds` ClusterRole (spec 13 §4.7) in `60-flowsdn-rbac.yaml`,
  and the operator's `flowsdn-operator` ServiceAccount and ClusterRole (spec 12 §4.8) in
  `63-flowsdn-operator-rbac.yaml`. Operator CRD `update` is limited by `resourceNames` to
  these 22 CRDs. A test checks both roles against the CRD set.

What does not exist yet: registration by an operator (stormcos applies `crds/` directly,
which is the reference's `--skip-crd-creation` mode), the agent's CRD readiness gate,
Rust types per kind, and the controllers that write `status`, emit events and garbage
collect. Applying a `FlowsdnNetworkPolicy` today stores it, validated, but nothing
enforces it. Each of these is tracked per group in the issues linked from #325.

## The kinds

| Kind | Short name | Scope | Status | What it is for | Written by |
|---|---|---|---|---|---|
| FlowsdnNetworkPolicy | `fsnp` | Namespaced | yes | L3/L4/L7 policy for endpoints or nodes in a namespace | users; operator sets `Valid` |
| FlowsdnClusterwideNetworkPolicy | `fscnp` | Cluster | yes | the same, cluster-wide, including host policies | users; operator sets `Valid` |
| FlowsdnCIDRGroup | `fscg` | Cluster | — | named external CIDR sets that policies reference | users, operator (`toGroups`) |
| FlowsdnEndpoint | `fsep` | Namespaced | — (in-object `status`) | one per pod: identity, addressing, policy enforcement | agent |
| FlowsdnEndpointSlice | `fses` | Cluster | — | batches of endpoints for large clusters | operator |
| FlowsdnIdentity | `fsid` | Cluster | yes | a numeric security identity and its labels | agent / operator |
| FlowsdnNode | `fsn` | Cluster | yes | per-node addresses, IPAM pools and health endpoint | agent; operator in cloud IPAM |
| FlowsdnNodeConfig | `fsnc` | Namespaced | — | per-node agent configuration overrides by node selector | users |
| FlowsdnLocalRedirectPolicy | `fslrp` | Namespaced | — | redirect a frontend (address or Service) to node-local backends | users |
| FlowsdnEgressGatewayPolicy | `fsegp` | Cluster | — | send selected pods' egress through gateway nodes with a fixed IP | users |
| FlowsdnEnvoyConfig | `fsec` | Namespaced | — | Envoy listeners/clusters for L7 traffic of selected Services | users, operator (Ingress/Gateway) |
| FlowsdnClusterwideEnvoyConfig | `fscec` | Cluster | — | the same, cluster-wide | users, operator |
| FlowsdnLoadBalancerIPPool | `fslbippool` | Cluster | yes | address pools for LoadBalancer Services | users; operator writes status |
| FlowsdnL2AnnouncementPolicy | `fsl2announcement` | Cluster | yes | which nodes answer ARP/NDP for which Service IPs | users; agent writes status |
| FlowsdnPodIPPool | `fspip` | Cluster | — | pod CIDR pools for multi-pool IPAM | users, operator (default pool) |
| FlowsdnBGPClusterConfig | `fsbgpcluster` | Cluster | yes | BGP instances and peers for a set of nodes | users |
| FlowsdnBGPPeerConfig | `fsbgppeer` | Cluster | yes | peer session settings: timers, auth, families | users |
| FlowsdnBGPAdvertisement | `fsbgpadvert` | Cluster | — | what is advertised: pod CIDRs, Service IPs, interfaces | users |
| FlowsdnBGPNodeConfig | `fsbgpnode` | Cluster | yes | the per-node BGP configuration derived from the above | operator; agent writes status |
| FlowsdnBGPNodeConfigOverride | `fsbgpnodeoverride` | Cluster | — | per-node router ID, ASN and port overrides | users |
| FlowsdnGatewayClassConfig | `fsgcc` | Namespaced | yes | parameters of a Gateway API GatewayClass | users; operator writes status |
| FlowsdnDatapathPlugin | `fsdp` | Cluster | — | registration of an external datapath plugin | users |

Printer columns are the reference's: for example, `kubectl get fsep` shows security
identity, enforcement, state and addresses, and `kubectl get fslbippool` shows disabled,
conflicting and available IPs. For the five kinds the reference leaves bare, flowsdn adds
its own (#298): `fscg` CIDRs, `fsdp` attachment and version, `fses` namespace and
identities, `fsnc` selector, `fspip` IPv4/IPv6 CIDRs, each with Age. A test checks every
column's JSONPath against the schema.

## Moving over from Cilium

Each Cilium kind maps to the flowsdn kind with the same schema. Change the API group and
the kind, and leave the spec as it is:

| Cilium (`cilium.io/v2`, `v2alpha1`) | Short | flowsdn (`flowsdn.io/v1alpha1`) | Short |
|---|---|---|---|
| CiliumNetworkPolicy | cnp | FlowsdnNetworkPolicy | fsnp |
| CiliumClusterwideNetworkPolicy | ccnp | FlowsdnClusterwideNetworkPolicy | fscnp |
| CiliumCIDRGroup | ccg | FlowsdnCIDRGroup | fscg |
| CiliumEndpoint | cep | FlowsdnEndpoint | fsep |
| CiliumEndpointSlice | ces | FlowsdnEndpointSlice | fses |
| CiliumIdentity | ciliumid | FlowsdnIdentity | fsid |
| CiliumNode | cn | FlowsdnNode | fsn |
| CiliumNodeConfig | — | FlowsdnNodeConfig | fsnc |
| CiliumLocalRedirectPolicy | clrp | FlowsdnLocalRedirectPolicy | fslrp |
| CiliumEgressGatewayPolicy | cegp | FlowsdnEgressGatewayPolicy | fsegp |
| CiliumEnvoyConfig | cec | FlowsdnEnvoyConfig | fsec |
| CiliumClusterwideEnvoyConfig | ccec | FlowsdnClusterwideEnvoyConfig | fscec |
| CiliumLoadBalancerIPPool | ippools | FlowsdnLoadBalancerIPPool | fslbippool |
| CiliumL2AnnouncementPolicy | l2announcement | FlowsdnL2AnnouncementPolicy | fsl2announcement |
| CiliumPodIPPool | cpip | FlowsdnPodIPPool | fspip |
| CiliumBGPClusterConfig | cbgpcluster | FlowsdnBGPClusterConfig | fsbgpcluster |
| CiliumBGPPeerConfig | cbgppeer | FlowsdnBGPPeerConfig | fsbgppeer |
| CiliumBGPAdvertisement | cbgpadvert | FlowsdnBGPAdvertisement | fsbgpadvert |
| CiliumBGPNodeConfig | cbgpnode | FlowsdnBGPNodeConfig | fsbgpnode |
| CiliumBGPNodeConfigOverride | cbgpnodeoverride | FlowsdnBGPNodeConfigOverride | fsbgpnodeoverride |
| CiliumGatewayClassConfig | cgcc | FlowsdnGatewayClassConfig | fsgcc |
| CiliumDatapathPlugin | cddp | FlowsdnDatapathPlugin | fsdp |

Fields that name another resource change with it: the `kind`, `group` and `apiVersion`
values a schema fixes (for example a policy's Envoy config reference, `FlowsdnEnvoyConfig`)
are the flowsdn ones. A `FlowsdnNetworkPolicy` converted from a `CiliumNetworkPolicy` keeps its
selectors, label keys (`k8s:io.kubernetes.pod.namespace`, ...) and rules unchanged.
flowsdn never reads, adopts or deletes `cilium.io` objects (ADR-0017). Cilium-written
objects (endpoints, identities, nodes, endpoint slices) are not migrated; the flowsdn agent
writes its own. Migrating policies is a manual `apiVersion`/`kind` edit today.
