## Remaining acceptance and owner input

The recovered code is still a library checkpoint. The agent does not start
Kubernetes watches, reconcile Node routes, or allocate/reconcile cluster-wide
identities and ipcache entries. Transport supervision still needs retry/backoff,
cache-sync fencing, initial-list fallback and event batching. Slim objects cover
only the fields currently needed by this checkpoint. Tests do not establish
complete specification 13 conformance.

The acceptance review also identifies remaining ADR obligations to audit:
map cleanup/retry ownership, identity restart/GC, reference endpoint restore,
health namespace ownership, API limiter/route contracts, rollback races,
neighbor management, device hotplug and rule-event recovery. Operator ownership
remains separate work in #296; static per-node IPAM is not a substitute.

The required disposable two-node IPv4/IPv6 gate needs a designated test target.
The managed test registry currently lists only a Cilium-edition machine. The
provisioning script referenced by #296 requires root SSH, prohibited by the
session rules. The owner or stormcentral must provision/register the flowsdn
pair, or identify an existing disposable pair and its non-root managed access.
No existing machine was repurposed. Running-component tests must use declared
requirements and isolated test-container Jobs, not hold a build slot.

Issue #291 stays open. No golden, release, version bump or networking acceptance
is claimed. The source version remains the milestone's foundation version.
