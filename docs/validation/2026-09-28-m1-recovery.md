## Remaining acceptance and owner input

The recovered code is still a library checkpoint. The agent does not start
Kubernetes watches, reconcile Node routes, or allocate/reconcile cluster-wide
identities and ipcache entries. Transport supervision still needs retry/backoff,
cache-sync fencing, initial-list fallback and event batching. Slim objects cover
only the fields currently needed by this checkpoint. Tests do not establish
complete specification 13 conformance.

The acceptance review also identifies remaining ADR obligations to audit:
map cleanup/retry ownership, identity restart/GC, reference endpoint restore,
health namespace ownership, API limiter/route contracts, rollback races,
neighbor management, device hotplug and rule-event recovery. Operator ownership
remains separate work in #296; static per-node IPAM is not a substitute.

The required disposable two-node IPv4/IPv6 gate needs a designated test target.
The managed test registry currently lists only a Cilium-edition machine. The
provisioning script referenced by #296 requires root SSH, prohibited by the
session rules. The owner or stormcentral must provision/register the flowsdn
pair, or identify an existing disposable pair and its non-root managed access.
No existing machine was repurposed. Running-component tests must use declared
requirements and isolated test-container Jobs, not hold a build slot.

Issue #291 stays open. No golden, release, version bump or networking acceptance
is claimed. The source version remains the milestone's foundation version.

## Final checkpoint: owner decision required

At pushed `03685f2`, Clippy with `-D warnings` passed for all targets in the
three selected crates; the 19 Kubernetes tests and 3 unprivileged loopback tests
passed again. The namespace fixture remained ignored. The managed run took
73 seconds and removed its drive. Its final dependency check could not start
because cargo-deny was absent (automatic failure #305).

A separate sc-build installed cargo-deny 0.20.2 under the disposable volume's
temporary directory and ran `cargo-deny --locked check` against `03685f2`.
That run took 109 seconds, exited 6 and removed its drive. It reported
`advisories ok, bans FAILED, licenses FAILED, sources ok`. The explicit ban is:

```text
crate 'cc = 1.5.1' is explicitly banned
cc -> (build dependency) ring 0.17.14 -> rustls/kube-client -> flowsdn-k8s
reason: No C compiler; ADR-0002
```

The license gate also failed; its individual diagnostics need retention on
the next policy run. No dependency-policy exception was added. Automatic
[issue #306](https://github.com/glennswest/flowsdn/issues/306) tracks this failure.
The recovered transport therefore is not an accepted or releasable checkpoint.

The existing Rust-only decision remains authoritative. The obvious pure-Rust
rustls provider candidate, [rustls-rustcrypto](https://github.com/RustCrypto/rustls-rustcrypto),
explicitly warns against production use in its upstream README as reviewed
on 2026-09-28. Selecting an experimental provider, or changing the existing
C-dependency policy, requires an explicit owner decision; neither was done.
Integration work is paused for that decision, with the two-node test target
also still required. All source and validation records are preserved on GitHub.
